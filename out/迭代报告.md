## 一、本轮改了什么（用户视角）

### 1. 坏备份进不来，也锁不死应用了

**之前**：导入备份只检查每条记录有没有 `id`，不查字段内容。一条 `date` 缺失或不是字符串的记录混在备份里，导入即被保存，之后排序比较器抛 TypeError，每次启动都崩在同一处，应用被彻底锁死；同时多处渲染把导入字段未转义直接拼进 HTML，恶意构造的备份可以注入脚本（存储型 XSS）。

**现在**：
- 导入时逐条规范化（`index.html:1524-1563` `importData` 重写，`index.html:1566-1620` `applyImport`）：`date` 必须是真实存在的 YYYY-MM-DD（`2026-13-45`、纯数字、乱串都拒收），数值字段强制 Number 化、垃圾串归空，生词必须含字符串 `addedAt`，成绩须 `total > 0`；无效条目跳过并计数，完成后 toast 汇报「新增 / 重复跳过 / 无效跳过」各多少条。
- 启动兜底（`index.html:883-905`）：读档时对 records / words / scores 逐条 normalize 过滤，旧版本已经存进 localStorage 的脏数据也会被清掉，启动链路不再崩溃；`settings.examDate` 经校验才采用（`index.html:917-920`），非法日期不再导致倒计时 NaN 并进入页面。
- 崩溃点防御（`index.html:962-965`）：排序比较器改为 `(b.date||'').localeCompare(a.date||'')`，date 缺失不再抛异常。
- XSS 封堵：打卡卡片、成绩档案、考试倒计时、生词列表的用户可控字段全部过 `esc()`（`index.html:1021-1027`、`1304`、`2133`、`1808`）。

### 2. 导入的「取消」真的取消了

**之前**：导入确认框把「取消」映射为「覆盖导入」（清空现有全部记录后导入），想放弃导入而习惯性点「取消」，反而触发清空。

**现在**（`index.html:743-757`、`1622-1638`）：改为三选弹窗「合并导入 / 覆盖导入 / 取消」——只有明确点「合并」或「覆盖」才动数据，取消、Esc、点背景一律中止且不改动任何数据；覆盖保留二次确认，文案如实列出将清空的「打卡记录、生词、成绩」三类数据；覆盖分支无条件重置三类数据，不再因备份缺 `scores`/`words` 键而残留旧数据（`index.html:1566-1573`）。

### 3. 「清空」名实相符，且可反悔

**之前**：按钮叫「清空全部数据」，实际只清打卡记录，生词、成绩、回收站都留着，提示却说「已清空全部数据」；更糟的是清空 2 秒后自动备份会把备份文件覆盖成空——用户特意开启的最后防线被清空动作自己销毁。

**现在**（`index.html:2751-2788`）：
- 文案统一为「清空 N 条打卡记录」，明示生词本与成绩档案不受影响；
- 已开启自动备份时，清空前先写一份带时间戳的快照文件（`readinglog-backup_snapshot_日期_时分秒.json`，`index.html:2123-2137`），不覆盖固定备份文件；快照写失败则中止清空；
- 未开备份时，确认文案明示清空后无法从备份文件夹找回；
- 清空后 6 秒 toast 带「撤销」，按 id 合并恢复，窗口期内新打卡的记录不会被误丢（`index.html:2779-2787`）。

### 4. 自动备份坏了会说，也会自己试着好起来

**之前**：任何一次写失败（磁盘满、备份文件夹被删/移动、文件被占用）都一律归类为「需要重新授权」，此后所有保存静默跳过备份、不提示、不重试，状态只在设置页 DOM 里，可能数周不知备份已停摆。

**现在**（`index.html:2077-2121`、`1997-2000`、`2140-2160`）：
- 按错误类型区分文案：需要重新授权 / 文件夹被删或移动 / 磁盘满 / 其他错误；
- 仅首次失败弹 toast（带「去处理」入口跳设置页），自动重试期间不打扰；恢复成功提示「自动备份已恢复 ✓」；
- 每次保存时若距上次尝试超 60 秒，自动 `queryPermission` 尝试恢复，不再永久静默停摆；
- 设置页状态文案与按钮（重新授权 / 重新选择文件夹 / 选择备份文件夹）随状态联动（`index.html:2050-2073`、`2677-2680`）。

### 5. 批量导入可以带日期了

**之前**：一次导入的全部记录共用同一个「导入日期」，补录多天积压全挤在同一天，连续打卡天数、日历分布、7/14/30 天复习到期时间全部失真。

**现在**（`index.html:1717-1770`）：
- 粘贴文本中可插入独立日期行（`YYYY-MM-DD`、`2026.1.5`、`2026/1/5` 均可），该日期作用于其后的记录；组前、组间、最后一组之后三种位置都生效；
- 非法日期行忽略；组已有显式日期时不被覆盖；与「年月」考试行互不混淆；
- 预览逐条显示指定日期（📅 标注）并汇总「N 条将使用文本中指定的日期」（`index.html:1786-1797`）；说明与输入框示例同步更新，「导入日期」标签改为「导入日期（未在文本中指定时使用）」（`index.html:471-480`）。

### 6. 独立复查实测出的 4 个新问题，本轮已修

复查（结论 ok=false）在修复结果上实测出 4 个问题，已全部修复并验证：

1. **尾部日期行不生效**：日期行写在「最后一组之后」被静默丢弃（原实现是不变式下的死代码），该记录回退到「导入日期」——正是本轮要修的挤同一天问题。修复：日期行分支不再关闭当前组，尾部场景由循环结束处回填接管（`index.html:1661-1667`、`1692-1695`）。当最后一组已由组间日期行获得日期时，尾部日期行丢弃而不覆盖已明确标注的日期；该歧义场景的解析结果在预览中逐条可见，导入前可确认。
2. **快照 toast 被覆盖**：清空时「已保存快照」提示与随后的清空提示在同一同步块先后触发，前者永远看不到。修复：快照信息并入清空 toast 文案（`index.html:2751-2788`）。
3. **清空撤销丢新记录**：撤销用整表替换 `records=backup`，6 秒窗口内新增的打卡记录被静默丢弃。修复：改为按 id 合并恢复并播报恢复条数（`index.html:2779-2787`）。
4. **回收站可恢复脏数据**：恢复按钮直接 push 原始 item，升级前已躺在回收站里的脏记录/脏生词恢复后可再次引发同类崩溃。修复：恢复前先 `normalizeRecord` / `normalizeWord`，无效条目拒绝恢复并提示，原始内容保留在回收站（30 天自动清理兜底）；`deleteRecord`/`deleteWord` 的 toast 撤销路径未动——其数据来自已规范化的内存数组（`index.html:2613-2629`）。

### 验证情况（修复与复查环节的留存记录）

- 语法：`node --check`（v24.15.0）对完整内联 `<script>` 校验通过（修复轮 FINAL_SYNTAX_OK、复查修复轮 SYNTAX_OK）；
- 逻辑：`node .v2c_logic_test.js` 35 项断言全部 PASS（normDateStr / normalizeRecord / normalizeWord / normalizeScore / parseBulkText 日期行等）；`node .v2c_recheck_test.js` 19 项断言全部 PASS（pass=19 fail=0，含复查员此前实测 FAIL 的尾部日期行场景）；两轮临时测试文件均已删除；
- **浏览器端人工测试未运行**（环境无浏览器，任务约束不要求）：导入三选弹窗、清空快照与撤销、备份错误提示、批量日期预览等 UI 流程未经实际点击验证；

## 二、发现但未修的问题与理由

### 已核验存在、本轮未修（建议优先处理）

- **删除 toast「撤销」会弹错回收站条目（high）**：撤销回调固定 `trash.pop()` 弹回收站栈顶（`index.html:1982-1989`、`1999-2006`，已核验）。先删记录再删生词后点撤销（或期间在回收站页恢复过其他条目），会把该生词从回收站静默永久移除、无法找回，且目标记录并未恢复。本轮按「存疑不修」处理，该路径未改动——这是当前已知未修问题中严重度最高的。

### 分诊剔除（问题真实，但影响面窄或超出本轮范围）

**低频打磨类**
- 今日清单守卫恒假（`index.html:2070-2075`）：零数据新用户首屏多显示一个「0/0」清单，纯外观、影响面极窄；
- 历史筛选状态脱节（`index.html:980-986`）：要先删掉/覆盖掉正在筛选的值才触发，表现为列表显示为空，手动切换下拉即恢复；
- Esc 在编辑态关不掉记录表单（`index.html:2303`）：仅与快捷键帮助文案不一致的小体验问题，且原报告自述为静态阅读、未实测。

**体验噪声类**
- 备份横幅不感知自动备份状态（renderBackupBanner）：误导性提示属体验噪声，无数据风险；
- 备份导出 payload 缺 trash（`index.html:1435-1451` exportData）：与 CHANGELOG 承诺不符，仅在「恢复备份且回收站恰有内容」时体现，宜随下次备份相关修复顺带。

**修复极简、因修复名额上限未入选**
- SW 对 404 错误页照单缓存（`sw.js:30-53`）：put 前加 `resp.ok` 校验即可，值得做。

**需结构性重构、建议单独立项**
- 渲染性能：renderAll 每次全量重建所有区块 DOM，历史/生词列表无分页（`index.html:901-916`、`1015`、`1725-1739` 等），几千条记录时每次保存明显卡顿（低端手机尤甚）。需要分页/虚拟化/按需渲染，单文件应用回归风险大，不宜挤占缺陷修复名额。

**功能增强（属 ROADMAP，非缺陷）**
- 生词本缺编辑入口（`index.html:1680-1683`、`1733-1737`）：改释义/补来源只能删除重建，莱特纳复习进度归零；重复添加也无法借此更新释义；
- 批量导入预览逐条改日期：本轮在「文本携带日期行」与「预览逐条编辑」两条路径中选择了改动更小的前者，预览为只读，需要逐条修改可在导入后用单条编辑表单；
- 多题库预设未打通矩阵/表单/成绩：体量大，考研用户可暂时手动适应，列为功能迭代；
- 成绩档案缺备考期对照、考后不引导录入：ROADMAP 承诺的功能增强。

### 有意取舍说明

- 清空不逐条塞回收站：回收站 200 条上限会截断整批清空的数据、逐条恢复不适用于批量场景，改用「清空前时间戳快照 + toast 撤销」实现同等可恢复性（快照写独立文件，不覆盖固定备份）；
- 复查修复第 1 项的歧义场景（尾部日期行 vs 组间已有日期）选择「不覆盖已明确日期」，避免误贴的日期行悄悄改掉数据；解析结果预览可见。
